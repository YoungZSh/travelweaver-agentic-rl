# 50 步统一因果图 SFT V4

## 目标

程序化 SFT 数据只接纳 50 个有效工具调用以内、Reward=1、全硬约束通过且零无效动作的
正常成功轨迹。线上 rollout 仍可保留额外 API turn，用于处理模型输出的无效动作。

轨迹不再按工具或分页次数拆成互斥 family。每道题先从同一张因果图中选择最短可行证据路径，
低频能力节点只有在题目与当前证据真正需要时，才自然接入已有的搜索、保存、路线和提交依赖链。

## 统一因果图

主干节点为：

```text
任务约束
  -> 目录查询（存在相应约束时）
  -> 题面约束驱动的候选搜索 / 有明确选择目标的分页
  -> 保存候选
  -> 路线查询
  -> 提交计划
```

低频节点不通过无意义调用补齐，而是在构图时接入主干：

- `check_place_open`：已检索并准备排入日程的地点 -> 开放验证 -> 保存或提交；
- `search_nearby`：已展示的路线端点或不同类型地点 -> 附近发现 -> 保存目标候选；
- `list_candidates` / `remove_candidate`：保存目标和真实同类备选 -> 显式价格比较 -> 删除较差备选。

三类证据路径可以出现在同一条轨迹中，不构成笛卡尔积，也不改变题型。第一轮主图不读取覆盖
门槛，只根据题目语义选择路径：题面点名且实际排入日程的景点或餐厅可以在计划访问时刻验证
开放，实际路线连续性可以走附近发现，预算或降低成本语义可以比较真实同类候选。第一轮完整
生成后再统计实际工具覆盖；不能自然
接入的题目不会被硬塞动作，也不会生成 `coverage_gap` 补丁。

目录工具只在题面明确要求对应类别、菜系、酒店属性或房型时调用；下一次搜索必须实际消费刚
展示的目录值。普通候选搜索不得复制隐藏 witness 的类别或名称。题面没有进一步筛选条件时，
只使用城市级公开搜索；题面明确“降低总花费”时才允许 `sort_by=price`。类别约束只作用于真正
匹配该约束的候选，不能把“一顿北京菜”错误扩展成所有餐厅都按北京菜搜索。

城市级或题面过滤搜索只有在存在公开、可核验的未决谓词时才能消费 cursor：题面点名的实体仍未
出现、题面明确要求的实体数量只完成了一部分，或者同一公开筛选条件需要多个不同实体而当前页
只找到其中一部分。不允许仅因为隐藏
witness 位于后页就写“继续寻找合适候选”。不单设 Discover Page Index；`next_page` 与其他工具
一样，任意连续段最多调用 3 次。没有公开分页理由的后页本地候选，只有在已确认的车站、酒店或
前序活动附近首屏可见时才可保留，并通过 `search_nearby` 发现。附近检索禁止再分页寻找预选
witness，否则合成阶段直接淘汰该 witness 并重采样。

## 全局动作约束

`next_page(cursor)` 与其他工具使用同一套约束，不再有 85%/10%/5% 的分页配额，也不限制整条
轨迹的分页总数。所有工具统一满足：

1. 任意工具最多连续调用 3 次；
2. 同一条轨迹禁止重复完全相同的 `tool + arguments`；
3. 点名搜索或真实的多实体数量缺口可按 cursor 继续；普通城市搜索、低成本排序和附近检索本身
   不构成翻页理由；
4. 整条轨迹最多 50 个有效工具动作；
5. 所有动作必须有效，最终提交计划并获得确定性 Reward 1.0。

Witness 按最终题面会公开的搜索条件检查可发现性。所有题面可见搜索最多连续调用 3 次
`next_page`；空间兜底必须位于既有行程锚点的附近首屏。Witness 最多使用 44 步，为 teacher 的
目录/低频证据节点预留最多 6 步，因此最终仍不超过环境的 50 步上限。

V5 进一步把“最多连续 3 次”与“允许翻页”拆开：连续上限只是安全边界，不是翻页理由。
无名称、无真实数量缺口的城市级后页 witness 会在任务合成阶段被淘汰；不能通过延长 Thought
模板为隐藏 witness 补造理由。既有 V4 任务需重新合成 witness 后才能进入 V27 程序化教师。

每条 synthesis record 记录共享策略：

```json
{
  "policy_version": "travelweaver-short-trajectory-policy-v5",
  "max_valid_steps": 50,
  "max_consecutive_tool_calls": 3
}
```

程序化生成和批次审计拒绝缺少或不匹配该策略、超过 50 步、含无效动作、出现相同动作重复，
或任意工具连续调用超过 3 次的记录。旧分页配额产物仅作为历史实验保留。

## 发布审计

每批至少报告：

- 全部 15 个公开工具的调用数、样本覆盖率和单轨迹最大调用数；
- 动作数及最长连续同工具调用的 min / p50 / p90 / max；
- 完全相同动作重复数和受影响样本数；
- 实际 `next_page` 次数分布（只观测，不作为预设配额）；
- Reward、RFT、官方 schema/commonsense 和因果 grounding 结果；
- Qwen 官方模板 token 长度和训练 wall-clock。

每个公开工具覆盖至少 10% 的样本是审计建议，样本数使用向上取整；例如 101 条批次的建议值是
11 条。10% 不是生成配额，也不要求任何工具精确等于该数量。未达到建议值时产物照常写出，报告
必须列出 warning 并向用户汇报；不得为了消除 warning 强制插入工具调用或改动其他自然因果路径。

ChinaTravel 官方 exporter schema 仍是批量接纳的硬门槛。固定官方 Common Sense 检查用于外部
兼容性观测，不作为 TravelWeaver 内部 Reward 已通过轨迹的否决条件；未全通过时必须在最终审计
中以非阻塞 warning 列出通过数、失败 task ID 和失败检查项，并向用户汇报。

当题面已有明确的景点数量要求时，witness 可以在已发现一个景点后，优先从同一公开搜索的
后续三页内选择可行候选来补足数量。该策略利用真实的数量缺口产生分页，不改变题型配额，也
不为普通任务制造无语义翻页。

先用相同的 100 道题比较程序化因果图 teacher 与 DeepSeek 自由 rollout，再决定 500/1,500 条
正式数据是否需要基于观测结果增加软分布控制。不要在对照实验前重新引入单工具硬配额。
